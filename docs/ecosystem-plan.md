## 固定语料与证据格式

优先复用台账中的生成器、测试和固定输入；固定清单而非不断扩大到所有文档：

| ID | 内容 / 主要检验 |
|---|---|
| C01 | 中文、Latin、Unicode 标点、标题与强调；文本与可见字形 |
| C02 | 水平/垂直合并与普通表格；逻辑网格、标签顺序和重复/遗漏 |
| C03 | 嵌套、跨页富内容表格；图片、拆分片段与重复表头 |
| C04 | 多级列表、跨 run 文本与真实格式/链接；标号与顺序 |
| C05 | 超链接、书签和字段可见结果；URI、目标与指令过滤 |
| C06 | 正文及表格 notes、可见/隐藏/未引用引用；锚点与回链 |
| C07 | 隐藏内容、未知部件及不支持语义；过滤、保留报告或损失诊断 |
| C08 | 默认/字符/段落/表格样式、参考样式、直接覆盖和 ID 冲突 |
| C09 | 混合字体、Arabic/Latin 格式边界、CJK fallback 与塑形开关 |
| C10 | 空段落、字号/行距/段前后间距、页眉页脚及固定行高 |
| C11 | keepNext、孤行、多栏、长列表/表格、分页与导航 |
| C12 | LTR/RTL 表格、兼容模式 12/14/15、零/逻辑边距与分节页边 |

每类允许少量明确参数变体，不增加全新功能作为该类通过条件。对现有模型无法表达的语义，
保留原包编辑路径或损失诊断，并登记具体缺口；不能靠预期错误的快照证明正确。
文件格式支持仍以 README 为准，不因语料涉及某结构就宣称完整 OOXML 兼容。

每阶段记录：Git 基线/候选、环境及依赖版本、输入摘要、复验命令、实际结果、失败及限制。
内容检查比较唯一标签/顺序/图片与 links，不仅比较字数；PDF 区分原始字节、规范化记录、
渲染像素和原生几何。变化页需视觉检查。没有实际产物的工具不能记为通过。
保留能复现关键结论的最少材料，避免每阶段复制全部既有摘要；引用稳定旧记录并补新增证据。

## 阶段顺序与发布门槛

### A0：范围与验收基线（当前）

交付本计划、初始 13 项映射、固定语料清单、待决策事项及已复现问题。
核对引用存在、原型可解析、范围无遗漏、历史与当前状态不混用；仅文档变化不重跑全套。
验收后先提交推送计划。随后按 A1 优先级执行，不需要另设例行确认步骤。

### A1：内容、安全与语义可信度（最高优先级）

覆盖 E01–E06/E08/E11–E13 的内容与错误处理边界。先核对现有安全/完整性测试覆盖，
补 C01–C09 中缺证据的组合；复现任何漏字、错误输出、隐藏内容泄漏、资源越界或失败污染后，
在本闭环修复共享根因及调用路径。依赖的可选工具实际安装/运行，不用 skip 充当通过。

完成条件：选定内容与安全清单每项有对应输入/断言/证据，支持内容无静默丢失，
不支持输入/语义有约定的拒绝或诊断，原包编辑及失败原输出保留；专项与适用集成通过。
审计公开选项，至少先关闭错误生效承诺和危险默认值问题；其余矩阵核对在 A4 汇总。
未解决的高优先级问题阻止进入优化阶段。

### A2：字体、布局与跨区域兼容闭环

覆盖 E05/E07–E10/E13。已复现空行问题归于 C10，连同标记字号、段落间距、预估/绘制、
正文/页眉/页脚路径一起处理，不再拆成多个一行修改阶段。C10–C12 的其他缺口按严重性合并处理。
原生对照必须记录差异；相同字体/固定度量可直接断言，字体替换和自然行距误差不能隐藏。

完成条件：上述固定布局清单无漏/重复/裁切、无限分页或导航错位；共享预估与实际布局一致；
真实 DOCX、独立 PDF 工具、Word/LibreOffice 产物验证受影响行为。未支持的分节/边框/文字语义
明确留在缺口清单，不因为基础样本通过就标为完成。完整引擎或标准认证由 D01/D02 决策。

### A3：有证据的性能与体积效率

以 A1/A2 验收后的稳定提交为基线；复用五类性能语料（小文档、百页、图文表格、重复图片、
混合样式）及小字号长表。先剖析瓶颈，再选择一个完整优化闭环。保留已有优化及其取舍记录：
[WOFF 重压缩](benchmarks/woff-recompression.json)、[宽度缓存](benchmarks/glyph-width-cache.json)、
[行布局内存](benchmarks/cell-line-slots.json)、[字体启动](benchmarks/font-glyph-names.json)。

同一语料/机器/配置、顺序交替至少七对独立进程；记录 import/parse/render/total、RSS、
输入输出大小及 wheel 字节。测试和文档更新时间不计为端到端优化证据。
改字体/塑形的优化同时验证普通与塑形路径；涉及结构标记的变化也验证标记输出。
校验字形覆盖、解码字体表/度量、字体许可、内容和渲染质量，不删除覆盖来换取体积。

完成条件：定位的瓶颈有对照证据；选择保留的候选有重复可见收益并明确量化代价。
时间中位收益不足 5% 或方向不稳定时，只记录未证明；体积变化与新增文档元数据分开。
不要求速度、内存、包/输出同时下降，也不把一种收益推广到所有后端。
若当前无值得保留的新优化，记录试验和理由，列为待决策而非擅自认定优化目标全部完成。
常驻原生服务吞吐选择见 D03。

### A4：安装、能力矩阵与收敛审计

逐项回填 E01–E13、C01–C12：实现 / 专项 / 共同样本 / 安装包 / 交付状态分别列证据。
最后生产候选在源码目录外安装 wheel，检查 imports/typing/fonts/licence 与源码一致，
运行适用集成、示例和现有 CI 矩阵。只有新增变化、失败或未解决风险才重复/扩大测试。
最终跨模块候选全量验证；纯文档重建可核对生产文件字节相同而不再次运行全部测试。

每个实现闭环通过其适用验收后更新文档/台账、按项目作者与共同署名约定提交推送；
准确报告该提交 CI 是否完成。最终完成需最新交付提交的适用 CI 通过，而非旧 SHA 的结果。
没有证据/外部产物/决策的事项逐条报告缺口，不用实现存在、测试数量或“未发现问题”代替完成。
